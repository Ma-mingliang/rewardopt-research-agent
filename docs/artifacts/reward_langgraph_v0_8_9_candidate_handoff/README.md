# Candidate Bank Handoff

## Why This Exists

This handoff package contains validation-ready semantic reward patches generated by the v0.8.8
real LLM proposal-only campaign. These patches are ready for training but have not been trained
due to current resource constraints (Windows pagefile limitations).

## Current Limitation

Training requires significant memory (pagefile > 32GB). This handoff preserves the candidate
artifacts so training can be executed when resource constraints are addressed or when a
CPU/low-resource training mode is selected.

## Recommended First Candidate

**test_control_energy_005** (Rank 1, score 0.626)

- Adds a quadratic control energy penalty: `control_energy = -0.01 * target_handle_angle ** 2`
- Lower complexity (0.16) than other candidates
- Focused, single-variable reward term
- Risk: possible under-actuation or slower correction

## Alternative Candidates

- **test_pbrs_001** (Rank 2, score 0.605): Risk penalty for high angular velocity or large error
- **test_curriculum_003** (Rank 3, score 0.605): Stability penalty for near-fall conditions

## How to Use Later

1. Choose a candidate patch from `candidate_patches/`
2. Apply it to HRRL2/env.py: `git apply candidate_patches/<template>.diff`
3. Run training (see `future_training_commands.md`)
4. Evaluate results
5. Restore baseline: `git checkout -- env.py`
